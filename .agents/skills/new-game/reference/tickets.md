# The ticket layers

`to-tickets` cuts vertical slices. For a whole title the slices still land in this order, because each layer is the seam the next one tests through. Each ticket is sized for one fresh context window; a layer that will not fit splits by suit, region, phase or panel, with the split tickets blocking the next layer together. Every ticket's acceptance criteria include the ones listed for its layer.

1. **Scaffold.** Both packages from the generators, catalogue entry in `config/config-games/src/games.json`, docs folder with the phase 0 and 1 files, `pnpm turbo run build lint check --filter=@tabletop/<slug>...` clean. Version 0.1.0, Alpha, beta.
2. **Component data.** Every row of `components.md` as typed data under `src/data/` or `src/components/`, ids permanent, with a data-integrity spec that counts each kind and checks every printed value the digest states.
3. **State model.** Schemas for game and player state with `Type.Static` types, the hydrated classes, the revision field, the turn manager and any round or phase manager, the canonical validator; the projected schema and `Visibility.protect` policies where anything is hidden. Specs: initialize, dehydrate, hydrate round-trips; the projection omits or redacts exactly what `visibility.md` says, for a player and a spectator.
4. **Actions.** One file per action with schema, validator, guard and hydrated class; registered in `apiActions` and the hydrator. Each records in `metadata` every fact its history sentence will need. Specs per action: accepted, refused with the reason, applied, metadata written, and the whole cascade asserted.
5. **Effects.** Card, tile or site effects through a registry keyed by component id and timing, with the printed text beside each registration. Specs: a reach sweep proving every component can be used by every route the rules allow, and a playthrough sweep proving every effect fires through the engine or names why not.
6. **Handlers and turn engine.** One handler per machine state, entry invariants, system actions for automatic consequences, the title's `util/` rule helpers. Specs: the turn-engine walk through every phase, a seeded replay-and-undo walk that compares final state, every state mapped to a handler.
7. **Definition and tournament.** `defineGame`, scoring, exploration, visibility registration, `competition.spec.ts` covering every player count and option with seat rotations and a fixed master seed; `visibility.spec.ts` and `actionProjection.spec.ts` where anything is hidden.
8. **Session and drafts.** The `GameSession` subclass, one draft object per staged flow on the shared staged-selection helpers, `undo()` override, the session harness that runs the real session in vitest. Specs: the five minimum tests per staged flow from `docs/user-interactions.md`.
9. **Table and panels.** `GameTable` on `DefaultTableLayout` and `ScalingWrapper`, the board layers, player panels, action panels and menus the contract names, the palette tokens in `app.css` scoped under `[data-game-ui="<id>"]`, the palette spec, the image coverage spec, fonts through `CustomFont`, the cover at 150px and 340px.
10. **Animation.** Animators through `AnimationContext` for the moves the contract's animation plan names, with the fast fallback and reduced motion; history replay creates no motion.
11. **History.** `ActionDescription` for every action type, read as the actor, another seat and a spectator; grouping through a pure aggregator; interstitials from the manager series; major events; nothing read from a patch.
12. **Contract scenarios.** Named table fixtures loadable in the browser, a Playwright spec per numbered scenario at desktop and phone viewports with touch, and the contract's exercise record filled in.
13. **Scripted complete game.** A scripted player per `reference/play-verification.md`, run for every player count and option, with replay, reverse Undo and cascade regeneration checks.
